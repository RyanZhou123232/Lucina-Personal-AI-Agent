# Memory v6：写入、检索与校验升级

## 统一行为

新增与纠正分开。`mode:add` 保留已有属性，重复值不再提交；同一个旧属性键承载独立事实时，以去重后的多个值保留。`mode:correct` 只替换或清空原话明确纠正的事实。新增不能覆盖已有核心字段；公司变更需要明确的当前状态纠正。取消计划只纠正计划，不更改当前公司。服务端绑定和数据库提交均执行这些约束。

字段修改历史记录 `operation:add|correct|unknown`。旧历史保留 `unknown`，不自动把过去的覆盖追认为正确纠正。事实是否失效由原始来源的含义决定：字段被覆盖本身不代表用户撤销了原事实。原文、来源边和历史不删除。

澄清最新指代时，允许完成此前尚未明确归属的事实，提案同时引用原事实和最新确认。多个可能人物时不能猜；被拒绝的提案或人物绑定警告可以触发一次修复，修复后再次绑定和校验。检索问题不会生成写入提案。

当前、历史、未来、取消分别表达。未来计划不升级为当前公司；“没有入职证据”不应写成“确定尚未入职”。原消息时间和相对时间原文继续保留，不猜具体日期。

回答围绕最后一条输入。旧问题不继续作为当前请求，旁白不触发旧事实重复提案。拟议结构化变更仍需 Review；模型不能把待审提案说成已经提交。

## 检索和引用

数据库检索继续使用所有者范围内的关键词、结构化状态、来源和来源上下文，不新增外部向量服务。结构化记录与原始消息分别排名并共享结果预算，避免单个通道占满候选。原始消息的前置用户上下文由 3 条扩大到 8 条；它用于解释指代，不直接充当引用事实。这个窗口仍有限，超出时应澄清，而不是猜人物。

人物记录保留全部原始来源与修改历史，因此更新公司不能使偏好来源消失。所有候选交由模型判断语义，不恢复姓名/最近位置的机械归属规则。数据库权限、排除当前查询消息、只使用用户原文等边界保持。

输出仅能使用本次检索提供的 `M` 引用。原始 UUID 和拼接错误的标签不能作为引用；精确来源校验同时覆盖检索回答和对话中的历史陈述。事实必须由其主要来源消息支持，不能借附近上下文为错误引用补证。

当检索有候选证据时，即使回答选择“无证据”，也接受独立校验，避免无条件放行误拒答。RELATED 不再自动添加笼统的拒答前缀，模型应直接表达该问题实际缺少的证据。
